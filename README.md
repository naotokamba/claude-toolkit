# claude-toolkit

Claude Code で使う道具の集まり。道具は `tools/<名前>/` に 1 つずつ置く。

| 道具 | 何をするか |
|---|---|
| [mode](#mode) | 会話に「今どのモードか」を持たせ、そのルールを毎ターン AI に渡す |
| [board](#board) | 作業の全体をカードで並べたボードをアーティファクトに作り、セッションに紐づける |
| [summary](#summary) | このセッションで今何をしているかを、決まった欄でまとめる |
| [close](#close) | このセッションを閉じてよいかを判断し、残っていることを片付ける |
| [next](#next) | 決めた順番どおりに 1 件ずつ進め、今の 1 件を毎ターン AI に渡す |
| [verify](#verify) | 直前の返事の主張を、一次資料と突き合わせて裏取りする |
| [ship](#ship) | 実装、レビューと修正の繰り返し、マージまでを一気に進める |
| [diagnose](#diagnose) | 会話の記録から、AI がモードのルールや返答の書き方を破ったターンを探す |

どの道具を使っていなくても、返答の書き方 `rules/writing.md` は毎ターン AI に渡す。

各コマンドの説明と引数は、`/` を打ったときの候補と `/help` に出る。`/bo` のように頭を打つと、そのコマンドだけに絞って見られる。

## mode

| 打つもの | 動き |
|---|---|
| `/mode purpose` `/mode diverge` `/mode converge` `/mode work` `/mode understand` `/mode infer` | 目的・発散・収束・作業・理解・推理の各モードに入る。順番は自由で、いつでも切り替えられる |
| `/mode d 期日に間に合わない件` | 切り替えて、続きの文をそのモードで話す |
| `/p` `/d` `/c` `/w` `/u` `/i` | `/mode p` などと同じ。`/d 期日に間に合わない件` のように続きの文も書ける |
| `/dc 議題` | 発散を会話ごと引き継ぐ fork に裏で任せ、受け取った案から絞って、収束モードで最初の論点と推奨まで出す。一覧は見せない |
| `/idc 議題` | Notion、Slack、リポジトリと Web の調査と発散を fork に裏で任せ、受け取った材料から絞って、収束モードで最初の論点と推奨まで出す。論点で使った事実には、文の中で根拠のリンクを付ける |
| `/w ok` | 作業モードに入り、それまでに決まったことと、まだ答えていない論点の推奨どおりに作業を始める |
| `/w ok <外すもの>` | 指定した論点は決めずに残し、残りを推奨どおりに決めて作業を始める |
| `/q` | モードを抜ける。`/mode off` と同じ |
| `/mode` | 今のモードと記録済みの目的を見る |
| `/mode off` | モードを抜ける |

| モード | 打つもの | 何をするか |
|---|---|---|
| 目的 | `/p` | 目的を決めるのに伴走する。言い切った目的は、そのまま記録する。<br>まだ 1 行になっていなければ 1 行の案を出し、合意したら記録して、以後は毎ターン AI に渡す。 |
| 発散 | `/d` | 目的を達成する手段を、過去事例や最新のやり方を調べながら広く出す。<br>良し悪しは決めずに、選択肢の一覧で終える。 |
| 収束 | `/c` | 外す理由を 1 行ずつ付けて選択肢を絞り、普通に使われている中で最良のものを基準にする。<br>答えによって道が変わる論点だけを、1 件ずつ推奨付きで出す。 |
| 作業 | `/w` | 決まったゴールに向けて、許可された範囲では確認を挟まずに最後まで進める。<br>ターンを返すときは、完遂したか、止めた理由、次にあなたがすることの形で報告する。 |
| 理解 | `/u` | 質問に答えるだけで、作業も提案もせず、答えで終える。<br>5 行までで、図や具体例を優先する。「詳しく」や抽象度を指定したときだけ長くなる。 |
| 推理 | `/i` | テーマについて推測を立て、Web やリポジトリ、Notion、Slack の一次資料で根拠を集めて確度を上げていく。<br>根拠は、文の中で重なる言葉にリンクとして付け、重ならないものは末尾の参考に並べる。事実と、確度付きの推測と、未確認に分けて書く。推測が変わったら、変えた根拠と並べる。 |

- 頭文字の `p` `d` `c` `w` `u` `i` と、日本語名の `目的` `発散` `収束` `作業` `実装` `理解` `推理` でも指定できる。表示は日本語のまま。
- 目的は、目的モードで合意したら AI が記録する。
- 作業モードでは、作業をしてターンを返すたびに、決まった形で報告する。完遂したか、止めた理由、揺らいだ決定事項、論点、次にあなたがすること。
- モードのルールは `tools/mode/modes/<モード>.md`、全モード共通のルールは `tools/mode/common.md`。新しいモードはファイルを足すだけ。

## board

| 打つもの | 動き |
|---|---|
| `/board` | ここまでの会話から、カードを並べたボードのアーティファクトを作る |
| `/board <URL>` | 既にあるボードを、このセッションに紐づける。セッションをまたいで同じボードを使える |
| `/board 見た目` | 紐づいたボードのページを、最新の雛形で公開し直す。データは触らない |
| `/board-issue <カードの名前>` | そのカードを親 issue に、中の作業を子 issue に書き出し、カードを閉じる |

- `/board <URL>` で紐づけたとき、このセッションに目的が記録されていなければ、ボードの目的をこのセッションの目的として記録する。
- ボードが紐づいていれば、論点に答えたとき、作業をしてターンを返したとき、目的を記録したときに、AI がボードを更新する。
- 見た目は `tools/board/skills/board/template.html`、データの形は `format.md`。中身はアーティファクトのデータベースに置き、ページは表示するだけ。
- 経緯やメモを書く欄は無い。`bin/claude-toolkit board check <フォルダ>` が形と字数の上限を検査し、上限を超えた文はページで赤い破線で囲まれる。
- アーティファクトの道具が使えるセッションでしか動かない。

## summary

| 打つもの | 動き |
|---|---|
| `/summary` | 目的、今のモード、どこまで終わったか、止まっている理由、次にあなたがすること、直近の決定事項、残件、ボードを、決まった欄で返す |

- 目的は、目的モードで記録したものをそのまま使う。記録が無ければ会話から推測し、推測だと書き添える。
- 打ったときだけ動く。

## close

| 打つもの | 動き |
|---|---|
| `/close` | このセッションを閉じてよいかを、「閉じてよい」か「まだ閉じない」で答える |

- 未コミット、未 push、issue の更新などは、コマンドで実際の状態を確かめる。
- 残っていることを、AI が今やれること、あなたの判断、あなたの手作業に分けて並べる。
- AI が今やれることは一覧を出して止まる。片付けてよい番号を返すと、その分だけ片付ける。
- 残っていることが無ければ、このセッションで作った一時ファイルと、マージ済みで変更の無い worktree を、聞かずに片付ける。残っていることがあれば、片付けない。

## next

| 打つもの | 動き |
|---|---|
| `/n` | 今の 1 件を終えて、順番の次の件に進み、その名前を出して止まる。順番が無ければ、ボードや issue、会話から番号付きで作って出し、認めたら記録する |
| `/n c` `/n idc` `/n w` など | 次の件に進んだうえで、そのコマンドを打ったのと同じに動く。続きの文が無ければ、今の 1 件がそのコマンドへの発言になる |

- 今の 1 件と順番の残りの数は、毎ターン AI に渡し、ステータスラインにも出す。AI は今の 1 件の話だけをする。
- 今の 1 件が大きすぎれば、「分けて」と言えば分けた先頭が今の 1 件になる。

## verify

| 打つもの | 動き |
|---|---|
| `/verify` | 直前の返事の主張を、主張ごとに「確かめた」「違った」「確かめられなかった」に分け、出典を付けて返す |
| `/verify <範囲>` | 指定した主張や範囲だけを確かめる |

## ship

| 打つもの | 動き |
|---|---|
| `/ship` | 実装を終え、Sonnet のレビューと修正を高と中の指摘が無くなるまで繰り返し、マージまで進める |
| `/ship pr` | PR を出したところで止める |

- 2 周目からのレビューには、直さないと決めた指摘とその理由を渡す。直さないと決めた指摘は、残りに数えない。
- 3 周しても収まらない指摘や、直すかどうかが自明でない指摘は、論点として止まる。
- 権限の確認や auto モードで止められた操作は、回り込まずにそこで止まる。

## diagnose

| 打つもの | 動き |
|---|---|
| `/diagnose` | このセッションの会話の記録を読み、AI がそのターンに渡されたモードのルールや返答の書き方を破ったところを、根拠つきで返す |
| `/diagnose <セッション ID>` | 指定したセッションを見る |

- 突き合わせる決まりは、今のファイルではなく、記録に残っている、そのターンに渡された文面。
- よく破られた決まりを回数の多い順に並べる。モードの文面を直すときの手がかりにする。
- 打ったときだけ動く。見つけて返すところまでで、文面は直さない。

## 道具を足すとき

`tools/<名前>/` を作り、必要なものを置く。

- `skills/<スキル名>/SKILL.md`：スラッシュコマンドの入口。インストールで各プロファイルにリンクされる。
- `tool.py`：フックやコマンドに組み込むもの。置けるものは `lib/toolkit/core.py` の先頭に書いてある。

スキルを足したときだけ、インストールをもう一度流す。中身の書き換えは、流さなくても次の発言から効く。

## インストール

```
bin/claude-toolkit install                 # ホーム直下の .claude と .claude-* すべて
bin/claude-toolkit install ~/.claude-work  # 指定したものだけ
bin/claude-toolkit install --dry-run       # 何が変わるかだけ見る
```

スキルのリンクと、`settings.json` へのフック・ステータスライン・許可ルールの追加を行う。何度流しても同じ結果になる。

## 外すとき

```
bin/claude-toolkit uninstall                 # ホーム直下の .claude と .claude-* すべて
bin/claude-toolkit uninstall ~/.claude-work  # 指定したものだけ
bin/claude-toolkit uninstall --dry-run       # 何が外れるかだけ見る
```

install で足したものだけを外す。このリポジトリを指すスキルのリンク、フック、ステータスライン、許可ルールの 4 つ。ほかの設定には触らず、書き換える前に settings.json のバックアップを残す。セッションの状態 `~/.local/state/claude-toolkit/` は残すので、要らなければ消す。

## 困ったとき

- `bin/claude-toolkit mode show 発散` で、そのモードで AI に渡す文面を確認できる
- フックは失敗しても会話を止めない。原因は `~/.local/state/claude-toolkit/error.log` に残る
- `CLAUDE_TOOLKIT_DEBUG=1` を付けて Claude Code を起動すると、フックが呼ばれた記録を `debug.log` に残す
- セッションの状態は `~/.local/state/claude-toolkit/sessions/<セッション ID>.json`
