このセッションを閉じてよいかを判断する。記録済みの目的、紐づいたボード、作業ディレクトリ、会話の記録ファイルの場所は、フックが `<claude-toolkit>` で渡している。

## 1. 状況を集める
確かめられることはコマンドで確かめる。会話の記憶だけで「済んだ」と書かない。
- **コード**：このセッションで触ったリポジトリを、作業ディレクトリと会話に出たパスから洗い出す。それぞれで、未コミットの変更、push していないコミット、マージしていない作業ブランチを、git で確かめる。マージ済みで変更の無い worktree とブランチは、残件ではなくゴミとして扱う。リモートのマージ済みブランチは見ない。
- **issue と PR**：会話に出たものを gh で開き、状態、最後の更新、最後のコメントを確かめる。
- **会話にしか無い決定事項**：issue、ボード、コミットのどこにも残っていない決定を探す。
- **返事待ち**：AI がユーザーに頼んだことや聞いたことで、答えが返っていないもの。AI が保留にしたもの。
- **動いているもの**：このセッションで始めた裏の作業、サブエージェント、サーバー、予約した作業。
- **ゴミ**：このセッションで作った一時ファイル、試験で作ったもの、設定のバックアップ、worktree。会話の記録ファイルで、このセッションで作ったものかを確かめる。ユーザーが残すと言ったものは、ゴミに入れない。中身に残すべきもの、たとえば調査の結果があれば、そのファイルは残件として扱い、issue などへ書き出すことを AI が今やれることに入れる。
- **ボード**：紐づいていれば、進行中のカードと判断待ち。
- **目的**：達成したか。達成していなければ、何が残るか。

## 2. セッションの種類を見分ける
- **issue 1 つを対象に進めていた**：その issue に、最新の状況と次の一手が書かれているかを中心に見る。
- **曖昧に進めていた**：残った課題を洗い出し、issue にする候補を作る。

## 3. ゴミを片付ける
判定が「閉じてよい」になるときだけ、答える前にゴミを片付ける。判定が「まだ閉じない」なら片付けず、ゴミの話も出さない。片付けたことも片付けなかったことも、報告に書かない。作業モードの「一時ファイルと worktree はそのまま置いておく」より、ここを優先する。
- 一時ファイル、試験で作ったもの、設定のバックアップは消す。
- worktree は `git worktree remove` で外し、そのブランチを `git branch -d` で消す。`--force` や `-D` は使わない。git が拒んだものは変更が残っているので、残件として扱い直し、判定を「まだ閉じない」にする。

## 4. 答える
次の見本と同じ Markdown で返す。全体をコードブロックで囲まない。見本の前後の「見本ここから」「見本ここまで」は書かない。当てはまるものが無い欄は「なし」と書く。

**AI が今やれること**
1. リポジトリ名 の push していないコミット 2 件を push する
2. issue の題とリンク に、最新の状況と次の一手を書く。書く要点を 1 行で
3. 新しく issue を作る。題を 1 行で

**あなたの判断**
- 問いを 1 つずつ

**あなたの手作業**
- 何をするかを 1 行。やると何が変わるかを 1 行

片付けてよい番号を返してください。全部なら「OK」で構いません。

- 3 つの欄がすべて「なし」のときだけ、判定を「閉じてよい」にする。そのときは最後の問いかけを書かない。
- issue と PR は、番号だけでなく題とリンクを書く。
- コマンドで確かめたことと、会話からの推測を分ける。推測には「推測」と書き添える。
- ゴミは一覧に入れない。消すかどうかを聞かない。

## 5. 返事を待つ
一覧を出したら止まる。返事が来るまで、push、issue への書き込み、issue の作成、削除をしない。

## 6. 片付ける
- 返事で OK が出た番号だけを片付ける。一部だけ OK なら、その分だけ片付ける。
- 新しく作る issue は、冒頭の 1 文で何をするタスクかを言い切る。それだけ読めば分かるように書く。決まっていないことを、決まったように書かない。
- 片付けた結果、残っていることが無くなったら、ゴミを片付けるの決まりどおりにゴミも片付ける。
- 片付けたら、作業モードの報告の形で返す。残ったものがあれば、判定を「まだ閉じない」のまま、残りを並べる。
