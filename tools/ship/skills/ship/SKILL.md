このセッションで進めている変更を、マージまで進める。引数が `pr` なら、PR を出したところで止める。引数が空でも `pr` でもなければ、何もせずに「使い方: /ship、/ship pr」とだけ返して終える。

## 止まる線
次の操作の前では、マージや apply の前に止まって論点にする。
- stg か prd に効く操作。stg か prd に配られる枝へのマージや、stg か prd への apply
- dev でも、データを持つ資源を消すか作り直す apply。DB、ストレージ、Key Vault など
- 人や外部への送信
- 秘密の値や権限の変更

これ以外は、dev への apply や合意した範囲を超えた直しも含めて最後まで進め、報告に書く。ユーザーが会話の中で止めなくてよいと言った操作は止めない。

## 1. 実装を終える
- 決まっている作業が残っていれば、先に実装を終える。
- まだ決まっていないことがあり、実装の形が変わるなら、論点として止まる。
- ブランチと worktree は、そのリポジトリの決まりとユーザーの指示ファイルに従う。
- リポジトリにテストや検査のコマンドがあれば、流して通す。全件を何度も流さず、落ちたものから先に通す。

## 2. レビューと修正を繰り返す
1. Sonnet のサブエージェントに、差分をレビューさせる。渡すのは、差分、変更の目的、リポジトリの決まりだけ。作った側の理屈や会話の経緯は渡さない。
   - 2 周目からは、これまでに直さないと決めた指摘も渡す。指摘ごとに「直さないと決めた。理由: 1 行」の形で書く。変更全体についての評価は書かない。
2. 指摘ごとに、重さを高、中、低に分けさせる。
3. 指摘ごとに、直すかどうかを決める。
   - 直すのが明らかなら直す。
   - 直さない理由が明らかなら、理由を 1 行で控えて直さない。
   - どちらか自明でなければ、論点として止まる。
4. 直したら、もう一度レビューさせる。
5. 高と中の指摘が無くなったら、ループを抜ける。直さないと決めた指摘は、残りに数えない。
6. 3 周しても高か中が残るなら、残った指摘を論点として止まる。

## 3. 出す
- コミットして push する。
- PR を出す。リポジトリに PR の雛形があれば、その見出しに沿って書く。
- コミットと PR に、モデル名を書かない。
- `/ship pr` なら、ここで止めて報告する。

## 4. マージする
- 引数が無ければ、マージまで進める。
- CI があれば、通るのを待つ。落ちたら直して、もう一度レビューの周回に戻す。
- マージの仕方は、そのリポジトリの決まりに従う。
- 権限の確認や auto モードで止められたら、そこで止めて報告する。止められた操作を、別の方法で回り込まない。
- 検査を飛ばすマージや、強制 push はしない。

## 5. 報告する
作業モードの報告の形で返す。次の 3 つを添える。
- PR の題とリンク
- レビューの周回数
- 直さなかった指摘と、その理由
- 合意した範囲を超えて直したこと
