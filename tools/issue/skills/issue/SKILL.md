引数: $ARGUMENTS

作業ディレクトリ、紐づいたボード、会話の記録ファイルの場所は、フックが `<claude-toolkit>` で渡している。

- 引数が「new」で始まらなければ、「使い方: /issue new issue にしたい中身」とだけ返して終える

## new のとき
1. 中身は、new のあとの文にする。文が無ければ、今の会話で話している件を中身にする。どちらからも読み取れなければ、「/issue new のあとに、issue にしたい中身を書いてください」とだけ返して終える。
2. 作る先のリポジトリを、中身、今の会話、作業ディレクトリから決める。決められなければ、候補を挙げて止まる。
3. 作る先のリポジトリの CONTRIBUTING.md の Issue の節と、ラベルの一覧を gh で読む。マイルストーンの決まりがあれば、それも読む。
4. 同じ中身の open な issue が既にないかを gh で探す。あれば作らず、その題とリンクを返して終える。
5. 中身のうち確かめられることは、その場で確かめる。確かめて起きた不具合なら修正の issue に、確かめていないものは調査の issue にする。
6. 書く。リポジトリの決まりとぶつかるところは、リポジトリの決まりに従う。
   - 題は、何をする issue かだけを、一目で分かる短い 1 文にする。調査なら、題の頭に「調査:」を付ける。日付と時刻の決まった当日の作業なら、題の頭に日付と時刻を付ける。
   - 本文の最初の 1 文で、何をするかと理由を伝える。そのあとに、確かめた方法と結果か、まだ確かめていない疑いであることを書く。根拠は、文の中で重なる言葉にリンクとして付ける。
   - ラベルは、リポジトリの決まりに沿って付ける。便に乗せる作業なら、その便のマイルストーンを付ける。
7. gh で作り、題とリンク、付けたラベルとマイルストーンを返す。issue の中身は返事に並べ直さない。
