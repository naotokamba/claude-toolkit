引数: $ARGUMENTS

モードの切り替えはフックが処理済みで、収束モードになっている。その結果を `<claude-toolkit>` として渡している。

- `<claude-toolkit>` が渡されていなければ、「モードのフックが入っていません。claude-toolkit の install を実行してください」とだけ伝えて終える
- 引数が無く、直前までの会話からも議題が読み取れなければ、「/idc のあとに、何について決めたいかを書いてください」とだけ伝えて終える

## 手順
1. 議題は引数の文にする。引数が無ければ、直前までの会話で決めようとしていたことを議題にする。
2. 調査を、Agent ツールの fork のサブエージェントに、調べ先ごとに並列で任せる。調べ先は Notion、Slack、リポジトリと Web の 3 つで、道具が無い調べ先は飛ばす。fork は会話をそのまま引き継ぐので、事情を書き直さなくてよい。fork には次の指示を渡す。
   - 議題の判断に効く事実を、一次資料で集める。推測には確度を高・中・低で付ける
   - 事実ごとに、根拠の URL を付けて返す。Slack はメッセージ、GitHub は行かコメント、Notion はページの URL にし、Notion は根拠の文をそのまま引用して添える
3. 調査の結果が揃ったら、発散を fork 1 つに任せる。fork は調査の結果も引き継ぐ。fork には次の指示を渡す。
   - 議題について、目的を達成する手段を広く出す。目の前の改善に加えて、制約そのものを動かす案や、上への提案、仕様変更の打診も含める
   - 良し悪しの判断と絞り込みはしない。1 案 1 行で、名前と短い説明の一覧を返す
4. fork が使えないときは、議題と、ここまでの会話の要点を添えて、普通のサブエージェントに同じ指示で任せる。
5. 調査の結果と発散の一覧は、ユーザーに見せない。発散の一覧を発散で出た選択肢として、収束モードのルールで絞り、論点 1 件と推奨を出す。
6. 論点で使った事実は、次の決まりで根拠にリンクする。文は、根拠のリンクが無い前提で書く。その文の中に根拠とぴったり重なる言葉があるときだけ、その言葉に根拠のリンクを付ける。重ならない根拠は、末尾に「参考」として並べる。URL はそのまま書かない。リンク先は、Slack ならメッセージ、GitHub なら行かコメント、Notion ならページにし、Notion はページの中で探せるよう根拠の文を引用してリンクにする。
