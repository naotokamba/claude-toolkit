引数: $ARGUMENTS

データの形は同じフォルダの format.md、見た目は template.html、更新の手順は update.md にある。
このセッションの ID、紐づけと検査のコマンド、会話の記録ファイルの場所は、フックが `<claude-toolkit>` で渡している。

ほかのファイルを読む前に、まずアーティファクトの道具がこのセッションで使えるかを見る。使えなければ、何も作らずに「このセッションではアーティファクトが使えません」とだけ返して終える。

引数が URL でも「見た目」でもなく、空でもないときは、何もせずに「使い方: /board、/board <ボードの URL>、/board 見た目」とだけ返して終える。

## 引数に URL があるとき
既にあるボードを、このセッションに紐づける。
1. データベースを読む道具で、`meta` と `cards` を作業用のフォルダに書き出す。
2. 検査のコマンドを通す。通らなければ、紐づけずに「このボードは今の形と違うので紐づけませんでした」と、通らなかった理由の上位 3 つを返して終える。データを直したり、書き込んだりしない。
3. 通れば、フックが渡した紐づけのコマンドに、その URL を付けて実行する。
4. 「ボードを紐づけました。判断待ちは n 件です。」と URL を返して終える。

## 引数が「見た目」のとき
紐づいたボードのページを、最新の template.html で公開し直す。データは触らない。
1. `<claude-toolkit>` に「このセッションのボード」が無ければ、「このセッションにボードが紐づいていません。/board <URL> で紐づけてください」とだけ返して終える。
2. データベースから meta/board を読み、title を控える。
3. template.html を作業用のフォルダに写し、`__BOARD_TITLE__` をその title に置き換える。
4. Artifact ツールで、写した HTML を `file_path` に、ボードの URL を `url` に渡して公開する。`icon` と `capabilities` は渡さない。前の版のものが引き継がれる。
5. 「ボードの見た目を最新にしました。」と URL を返して終える。

## 引数が無いとき
`<claude-toolkit>` に「このセッションのボード」があれば、その URL を 1 行で返して終える。
無ければ、新しく作る。
1. ここまでの会話から拾う。
   - 目的
   - ボード全体のゴール
   - 話題ごとのカードと、それぞれのゴール
   - カードの中の作業と、その種類。種類は、やるだけ、判断待ち、済みのどれか
   - 決定事項
2. 会話の前半が要約されて細部が消えているなら、フックが渡した記録ファイルから拾い直す。記録ファイルは大きいので、Sonnet のサブエージェントに読ませ、要点だけ受け取る。
3. 判断待ちの作業には、format.md の論点の形で ronten を書く。調べれば分かることは、書く前に調べる。
4. 作業用のフォルダに、`meta/board.json` と `cards/<id>.json` を置く。検査のコマンドを通るまで直す。
5. template.html を作業用のフォルダに写し、`__BOARD_TITLE__` をボードの名前に置き換える。
6. Artifact ツールで公開する。渡すものは次の 4 つ。
   - `file_path`：写した HTML
   - `icon`：`"board"`
   - `description`：何のボードかを 1 文
   - `capabilities`：`{"db": {"rules": [{"path": "", "write": "admin"}]}}`
7. データを書き込む。ArtifactData の batch、または Artifact の write_db の batch で、全文書を set する。
8. 書き込んだデータを読み直し、文書の数が合っていることを確かめる。
9. フックが渡した紐づけのコマンドで、ボードの URL をこのセッションに紐づける。
10. 「ボードを作りました。判断待ちは n 件です。」と URL を返して終える。

## 決まり
- AI のメモを残したいときは、ボードとは別のアーティファクトにする。ボードに書かない。
