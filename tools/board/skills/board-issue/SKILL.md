このセッションに紐づいたボードから、指定したカードを issue に書き出す。
ボードの URL、検査のコマンドは、フックが `<claude-toolkit>` で渡している。データの形と更新の手順は、board スキルのフォルダの format.md と update.md にある。

ほかのファイルを読む前に、まず次の 2 つを見る。当てはまれば、何もせずにその 1 行だけ返して終える。
- ボードが紐づいていない：「このセッションにボードが紐づいていません。/board <URL> で紐づけてください」
- アーティファクトの道具がこのセッションで使えない：「このセッションではアーティファクトが使えません」

指定したカードが見つからなければ、近い名前のカードを挙げて、どれかを聞いて終える。

## 書き出し方
- カードを親 issue に、カードの中の「済み」以外の作業を 1 つずつ子 issue にする。
- 書き出し先のリポジトリと題の頭は、meta/board の issue に従う。無ければ、それを論点として 1 回だけ聞く。
- 子 issue の書き方
  - 冒頭の 1 文で、何をするタスクかを言い切る。形は「〜するタスク」「〜を解決するタスク」「〜の解決方法を考えるタスク」のどれか。
  - それだけ読めば分かるように書く。ボードや会話を読まないと分からない言葉を使わない。
  - 今の状態、決まっていること、決まっていないことを分けて書く。決まっていないことを、決まったように書かない。
  - 判断待ちの作業は、カードの論点を「決めること」として書く。
- 親 issue には、カードのゴールと子の一覧を書く。移さないと決めたものがあれば、その一覧も書く。
- 既にある issue と重なるものは、新しく作らない。それを子につなぐか、付け替える。どうするかが自明でなければ、論点として聞く。

## 手順
1. 書く前に、コードや既存の issue で事実を確かめる。重い調べ物は、Sonnet のサブエージェントに並行して任せる。
2. 下書きを作業用のフォルダに書き、読み手役のサブエージェントに点検させる。高と中の指摘が無くなるまで直す。
3. 親、子の順に issue を作り、子を親の sub-issue につなぐ。
4. ボードを更新する。
   - カードの state を「issueに移した」にする
   - カードの issue に親のリンクを入れる
   - 各作業の issue に子のリンクを入れる
   - 検査のコマンドを通してから書き込む
5. 作業モードの報告の形で返す。作った issue は、リンクと題の一覧で示す。
