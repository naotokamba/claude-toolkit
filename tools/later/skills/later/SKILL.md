引数: $ARGUMENTS

作業ディレクトリ、紐づいたボード、会話の記録ファイルの場所は、フックが `<claude-toolkit>` で渡している。

## 1. 集める
確かめられることはコマンドで確かめる。会話の記憶だけで ○ にしない。
- 別の日にやると決まった作業を、このセッションの会話、紐づいたボード、作業ディレクトリのリポジトリから洗い出す。引数で範囲が指定されていれば、それに従う。会話の前半が要約で消えていれば、会話の記録ファイルから拾い直す。
- それぞれが、どの issue に書かれているかを gh で開いて確かめる。issue に書かれていない作業は × にする。
- 関わるリポジトリで、期日の過ぎたマイルストーンに open のまま残っている issue を gh で集める。

## 2. 確かめる
次の 4 つがすべてそろっていれば ○、1 つでも欠ければ × にする。
- 1 日に 1 つの issue になっている。日付の違う作業が同じ issue に混ざっていない
- 題の頭に、その日付と時刻がある
- その便のマイルストーンが付いている
- 本文の頭に「いつ」「何を見れば始められるか」「終わったと言える状態」がある

## 3. 答える
次の見本と同じ Markdown で返す。全体をコードブロックで囲まない。見本の前後の「見本ここから」「見本ここまで」は書かない。

見本ここから

**別の日の残作業**
- ○ 11/26 22:00 prd の apply：issue の題とリンク
- × 11/26 の server-test の作業：issue の題とリンク。欠けているものを 1 行で

**期日の過ぎたマイルストーンに残っている issue**
- issue の題とリンク：マイルストーンの名前

**直す中身**
1. 何をどう直すかを 1 行
2. 何をどう直すかを 1 行

直してよい番号を返してください。全部なら「OK」で構いません。

見本ここまで

- 当日の手順は返事に並べ直さない。issue へのリンクで済ませる。
- 期日の過ぎた issue は、閉じるか、次の便へ移すかを直す中身に入れる。どちらにするかは issue と会話から判断し、判断できなければ推測と書き添える。
- × も期日の過ぎた issue も無ければ、「別の日の残作業は、どれもその日に issue を見れば進められます」の 1 行と ○ の一覧だけを返し、問いかけは書かない。

## 4. 返事を待つ
一覧を出したら止まる。返事が来るまで、issue の書き換え、作成、クローズをしない。

## 5. 直す
- 返事で OK が出た番号だけを直す。
- 日付の違う作業が混ざった issue を分けるときは、日付ごとに新しい issue を作り、2. の形にそろえる。元の issue には、分けた先へのリンクを残す。
- 直したら、作業モードの報告の形で返す。
